## The Three OAuth Clients Explained

### 1️⃣ Web OAuth Client

**Purpose:** Backend token verification

**Configuration:**

```
Type: Web application
Name: CART Web Client
Client ID: 113273912716-xxxxx.apps.googleusercontent.com
Package Name: N/A
SHA-1: N/A
Authorized Origins: https://cartshop.site
```

**Used in:**

- `frontend/services/socialAuth.ts` (line 28)
- Backend API for verifying id_token

**Why needed:**
The mobile app requests an `id_token` with the **audience (aud)** set to this Web Client ID. Your backend verifies the token matches this audience.

---

### 2️⃣ Android OAuth Client #1 (Upload Key)

**Purpose:** Development & testing builds

**Configuration:**

```
Type: Android
Name: CART Android (Upload Key)
Client ID: Auto-generated by Google
Package Name: com.cart.hypermarket
SHA-1: E6:ED:21:31:EE:78:08:B1:EC:B2:03:BF:B4:83:EF:10:78:AC:F3:46
```

**SHA-1 Source:**

```bash
eas credentials --platform android
```

**Used when:**

- Running `npx expo run:android`
- Testing APK built with EAS
- Development builds
- APKs you manually install (side-loading)

---

### 3️⃣ Android OAuth Client #2 (Play Store Key)

**Purpose:** Production app from Google Play Store

**Configuration:**

```
Type: Android
Name: CART Android (Play Store Key)
Client ID: Auto-generated by Google
Package Name: com.cart.hypermarket
SHA-1: [Different SHA-1 from Play Console]
```

**SHA-1 Source:**
Google Play Console → Setup → App signing → "App signing key certificate"

**Used when:**

- App downloaded from Google Play Store
- Google re-signs your app with their key
- Production users

**⚠️ Critical:** Create this AFTER uploading to Play Console!

## Why You Need THREE OAuth Clients

### Scenario 1: Development (Local Testing)

```

        ▼

        │
        ▼

        │
        ▼

        │
        ▼

        ▼

```

### Scenario 2: Production (Play Store)

```

        │
        ▼

        │
        ▼

        │
        ▼
Google validates against: Android Client #2 ✅
        │
        ▼

        ▼

```

        │

        ▼

### What Google Validates

When a user tries to sign in, Google validates:

```
┌─────────────────────────────────────┐

│  com.cart.hypermarket              │ ────────────┐
└─────────────────────────────────────┘             │
                                                     ▼
                                            ┌──────────────┐
                                            │ OAuth Client │
                                            │  Package     │
                                            └──────────────┘
                                                     │
┌─────────────────────────────────────┐             │
│  App's Signing Certificate SHA-1    │  Must match │
│  E6:ED:21:31:EE:78:...             │ ────────────┘
└─────────────────────────────────────┘
```

**Both must match** for sign-in to succeed!

## Token Structure & Verification

### id_token (JWT) Structure

```json
{
  "header": {
    "alg": "RS256",
    "kid": "abc123"
  },
  "payload": {
    "iss": "https://accounts.google.com",
    "aud": "113273912716-xxxxx.apps.googleusercontent.com",  ← Web Client ID
    "sub": "123456789",
    "email": "user@gmail.com",
    "email_verified": true,
    "name": "John Doe",
    "picture": "https://...",
    "exp": 1710360000,
    "iat": 1710356400
  },
  "signature": "..."
}
```

### Backend Verification Process

```python
# Example in Python (similar in any language)

def verify_google_token(id_token):
    # 1. Fetch Google's public keys
    jwks = fetch_google_jwks()

    # 2. Decode header to get 'kid' (key ID)
    header = jwt.get_unverified_header(id_token)
    kid = header['kid']

    # 3. Find matching public key
    public_key = find_key_by_kid(jwks, kid)

    # 4. Verify signature & decode payload
    payload = jwt.decode(
        id_token,
        public_key,
        algorithms=['RS256'],
        audience=WEB_CLIENT_ID,  # ← Must match!
        issuer='https://accounts.google.com'
    )

    # 5. Check expiration
    if payload['exp'] < time.now():
        raise TokenExpired()

    # 6. Extract user info
    return {
        'email': payload['email'],
        'name': payload['name'],
        'google_id': payload['sub']
    }
```

## Common Mistakes & Fixes

### ❌ Mistake 1: Using Android Client ID in frontend

```typescript
// ❌ WRONG
const GOOGLE_WEB_CLIENT_ID = "xxxxx-yyyyy.apps.android.com";
```

**Fix:** Use **Web Client ID**, not Android Client ID!

```typescript
// ✅ CORRECT
const GOOGLE_WEB_CLIENT_ID = "xxxxx-yyyyy.apps.googleusercontent.com";
```

---

### ❌ Mistake 2: OAuth Consent Screen in Testing mode

```
Status: Testing
Published status: Not published
```

**Result:** Only test users can sign in!

**Fix:** Click **"Publish App"**

---

### ❌ Mistake 3: Missing Android Client #2

```
[X] Web Client
[X] Android Client #1 (Upload Key)
[ ] Android Client #2 (Play Store Key)  ← Missing!
```

**Result:** Google Sign-In works in development but fails in production!

**Fix:** Create Android Client #2 with Play Store's SHA-1

---

### ❌ Mistake 4: Wrong package name

```
app.json:        com.cart.hypermarket
OAuth client:    com.cart.marketplace  ← Typo!
```

**Result:** "Developer Error"

**Fix:** Ensure package name matches EVERYWHERE
